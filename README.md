# Design: Architecture Blueprint

Bob acts as an architecture partner to translate requirements and design principles into a target architecture for modernizing onto OpenShift.

## What this demonstrates

- Bob reads requirements, design principles, and integration maps
- Bob proposes a target component architecture
- Bob identifies integration boundaries and open design questions
- Bob writes Architecture Decision Records (ADRs)

## The scenario

Acme Commerce has completed planning (see the Plan & Analyze example). Now the team needs a target architecture. They've defined design principles (stateless, externalized config, horizontal scaling) and mapped their integrations. Bob needs to turn this into a concrete blueprint.

## Try it

1. Browse the `inputs/` folder to see the design inputs
2. Ask Bob: **"Review the inputs and summarize the key design constraints."**
3. Ask Bob: **"Propose a target component architecture for Acme Commerce on OpenShift."**
4. Ask Bob: **"Write ADRs for the key architecture decisions."**
5. Ask Bob: **"Generate the full architecture blueprint document."**
